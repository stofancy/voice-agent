## 2. 技术可行性分析

|--------|------|
| **API 支持** | `qwen3-asr-flash` 支持 OpenAI 兼容模式 |
| **流式输出** | 支持流式识别，可边说边返回 |

## 3. 方案对比

### 方案 A: 独立 STT + TTS + OpenClaw Agent

```
浏览器 → WebSocket → Voice Agent Plugin → STT API
                                     ↓
                              OpenClaw Agent
                                     ↓
                                TTS API → 浏览器
```

**优点**:
- ✅ 完全控制每个环节
- ✅ 可灵活切换 STT/TTS 提供商
- ✅ 深度集成 OpenClaw Agent
- ✅ 可调用工具和知识库

**缺点**:
- ❌ 复杂度较高
- ❌ 需要协调多个 API
- ❌ 延迟累积（STT + Agent + TTS）

**延迟估算**: 
- STT: ~500ms
- Agent: ~1000ms
- TTS: ~300ms
- **总计**: ~1800ms

**推荐指数**: ⭐⭐⭐⭐⭐ (MVP 首选)

---

### 方案 B: 百炼 Realtime 端到端

```
浏览器 → WebSocket → 百炼 Realtime API → 浏览器
                    (内置 STT+LLM+TTS)
```

**优点**:
- ✅ 简单，单一 API
- ✅ 延迟最低（~800ms）
- ✅ 已有 SDK 参考

**缺点**:
- ❌ 无法集成 OpenClaw Agent
- ❌ 无法调用工具和知识库
- ❌ 黑盒，可控性差

**延迟估算**: ~800ms

**推荐指数**: ⭐⭐ (不满足核心需求)

---

### 方案 C: 混合方案（Realtime STT + OpenClaw + TTS）

```
浏览器 → WebSocket → Voice Agent Plugin → 百炼 STT
                                     ↓
                              OpenClaw Agent
                                     ↓
                                TTS API → 浏览器
```

**优点**:
- ✅ STT 用 Realtime，延迟低
- ✅ 保留 OpenClaw Agent 集成
- ⚠️ TTS 独立，可控

**缺点**:
- ⚠️ 复杂度中等
- ⚠️ 需要协调两个 API

**延迟估算**: 
- STT: ~300ms (Realtime)
- Agent: ~1000ms
- TTS: ~300ms
- **总计**: ~1600ms

**推荐指数**: ⭐⭐⭐⭐ (优化方案)

## 4. 推荐方案

### MVP 阶段：方案 A（独立 STT + TTS + OpenClaw Agent）

**理由**:
1. **满足核心需求**: OpenClaw Agent 集成是必须的
2. **技术成熟**: 所有组件都有成熟 API
3. **可控性强**: 每个环节都可优化
4. **可扩展**: 后续可升级到方案 C

### 优化方向（Phase 2）

1. **STT 优化**: 考虑 Realtime STT 降低延迟
2. **TTS 优化**: 流式播放，降低等待时间
3. **Agent 优化**: 流式输出，边生成边 TTS
